Overview

A prompt bar that ships working products

AutoQ collapses the space between an idea and a running product into a single input. You type what you want — "make a live dashboard website to track personal transactions that fully works" — pick a model and effort, and choose whether to Plan first or Run immediately. AutoQ queues the work, builds it end to end, and returns something you can actually open.

The interface is deliberately calm: one field, a model selector, a mic for dictation, and a send button. Everything hard — decomposition, retries, verification — happens behind that quiet surface. finboard is one product built entirely through it.

Problem

AI tools stall between "chat" and "done"

Most AI builders hand you a wall of chat and half a result. You steer every step, copy code between windows, restart when something breaks, and still end up with a demo rather than a product. The cognitive load moves from doing the work to managing the tool that's supposed to do the work.

The friction isn't the model — it's the interface around it. There's no clear moment to say "just go," no confidence the thing will finish, and no honest signal about whether the output actually runs.

Design Principles

One input. Two intents. A real result.

AutoQ reduces the surface to a single prompt and one decision: Plan when you want to see the approach first, Run when you trust it to go. Model and effort ("Fable 5 · High") sit inline, so tuning the work never means leaving the field.

Behind it, work is queued and driven to completion — retries, verification, and assembly are the tool's job, not yours. The promise is finish-ability: what comes back opens and works.

Core Features
01
Plan or Run
One toggle sets intent. Plan drafts an approach you can read and adjust; Run kicks off the build immediately. Same prompt, two levels of trust — no separate flows to learn.
02
Inline model & effort
Choose the model and how hard it should think — "Fable 5 · High" — right inside the composer. Dial power up for a full product, down for a quick pass, without opening settings.
03
Queue that finishes
AutoQ owns the loop: decompose, build, retry, verify, assemble. You get a running result and a clear status — not a transcript you have to babysit to the end.

The proof is a shipped app. See what AutoQ built — finboard.

AutoQ is a bet that the hard part of AI tooling is no longer capability — it's the interface's willingness to take responsibility for finishing. By collapsing the flow to one field and one Plan/Run decision, and by making "done and running" the contract, the tool gets out of the way. finboard is the receipt: a real, working product that came out the other side of a single prompt.
